* Using this configuration
This file is the source of truth for the configuration loader. Each section explains a part of the setup and loads its implementation from =lisp/=. Edit those Lisp files for implementation changes and this document for imports and explanations.

Deferred features and future work are tracked in [[file:ROADMAP.org][ROADMAP.org]].

Doom's =:config literate= module tangles the source blocks into =config.el= during =doom sync= and when saving this document once the module is active. Do not edit the generated =config.el= directly. Tangling updates the file on disk; restart Emacs to apply configuration changes to the running session.

The imports below run in document order. Keep the macOS native compilation setup first, and set the Org directory before loading any code that needs Org.

Custom commands intended for =M-x= or keybindings use =my/=. Internal helpers, hooks and advice use =my--=; custom variables use =my-=. Internal modes and their associated keymaps keep the shared =my--= prefix so Emacs can derive their related names consistently.

#+begin_src emacs-lisp
;;; $DOOMDIR/config.el -*- lexical-binding: t; -*-
;; Generated from config.org. Edit config.org or the files under lisp/ instead.
#+end_src

* Completion and documentation
Vertico keeps a fixed completion height even after delayed theme previews.
Fixed-height sessions reserve blank display rows when there are fewer matches;
these are not selectable candidates. Dynamic-height sessions are unchanged.
[[file:lisp/completion-config.el][completion-config.el]] reduces automatic completion's idle delay to 150 ms. Completion documentation appears after 250 ms initially and 500 ms when changing candidates; echo-area documentation uses a 300 ms idle delay.

* Navigation
After =SPC w >=, =SPC w <=, =SPC w += or =SPC w -=, repeat or switch resize
directions with bare =>=, =<=, =+= and =-=. Use === to balance splits, =C-h=
for resize help, or =q=/=C-g= to exit. Any other key exits and runs normally.

[[file:lisp/navigation-config.el][navigation-config.el]] extends Doom's Nav Flash to counted Evil vertical motions of at least 10 lines, including visual-line motions in Org and the custom upward motion in Magit. Successful Avy jumps such as =g s s= also flash their destination. Ordinary single-line movement stays quiet; Doom's exclusions and the clock popup's flash suppression still apply.

Evil Snipe searches for literal whitespace, preserving Vim's =t<Space>= behavior: stop before the space and exclude it from a visual selection.

Evil's lowercase word motions (=w=, =b=, =e=, =ge=) and =iw=/=aw= text objects use Vim-style word boundaries: letters, digits and underscores belong together; punctuation such as hyphens and dots separates words. Uppercase =WORD= motions still follow whitespace boundaries. The syntax table is changed only during these Evil operations, leaving Emacs word commands and language-mode syntax unchanged.

* Text layout and line length
[[file:lisp/text-layout-config.el][text-layout-config.el]] replaces the vertical column guide with a theme-aware background tint on excess source columns in code. The default code limit is 80, Python uses 88, and Rust uses 100. Org and Markdown prose, terminals and generated buffers such as Magit and help are excluded from overflow highlighting.

Org and Markdown use visual wrapping with automatic hard filling disabled. Keep each prose paragraph on one source line, with blank lines between paragraphs; the display wraps to the available width. Source lines have no enforced length limit. =M-q= remains available for deliberately hard-wrapping a paragraph at =fill-column= (100 by default for prose), but is not needed for normal writing. Code and literal blocks retain their source line breaks. Code files remain unwrapped and use their formatter. Project-specific =fill-column= values in =.dir-locals.el= override the defaults; code highlighting follows =fill-column=. Formatter settings remain independent.

* Org
Heading padding uses display-only spaces, so hidden stars stay hidden over cursor-line and visual-selection backgrounds. Source view retains the real heading stars.

[[file:lisp/org-config.el][org-config.el]] sets the notes directory and uses visible-line numbering in Org buffers so folded text does not contribute hidden lines to the count. Org starts in editing view: proportional prose with monospace code and tables, with hidden markup revealed at the text cursor. The =SPC m v= view menu offers:

| Key | Action                                           |
|-----+--------------------------------------------------|
| e   | Editing: mixed pitch, markup at cursor, editable |
| r   | Reading: mixed pitch, hidden markup, read-only   |
| s   | Source: monospace, visible markup, editable      |
| m   | Toggle mixed pitch                               |
| h   | Toggle revealing hidden markup at the cursor     |
| w   | Toggle read-only                                 |

Selecting a preset resets these options; individual toggles adjust the buffer. Source view also disables Org Modern decorations and image/LaTeX previews. Markdown retains its direct =SPC m v= mixed-pitch toggle. The read-only toggle is the same command as =SPC t r=. Doom's =SPC t v= Visible mode reveals all invisible text rather than only markup at the cursor; selecting an Org view turns it off. Wrapping (=SPC t w=), line numbers (=SPC t l=), centring (=SPC t o=), padding (=SPC t P=), Zen and slides remain separate controls. The directory must be configured before Org loads.

* Python environments, language servers and formatting
[[file:lisp/languages/python-config.el][python-config.el]] selects one local Python language server at startup: =ty= first, then =pyrefly=, then =basedpyright-langserver=, then =pyright-langserver=. Ruff (=ruff server=) runs alongside the selected server when available, providing lint diagnostics, fixes and import organization. An explicit Python-buffer client allowlist prevents competing primary servers from running together. Selection uses Emacs's local =PATH=. Use =M-x my/python-lsp-switch= to select =auto=, =ty=, =pyrefly=, =basedpyright= or =pyright= for this Emacs session. The command reconnects active local Python buffers and updates future buffers; =auto= rechecks executable availability and restores the fallback order. Explicit choices require their executable. Remote connections are left alone. Keep the existing =+pyright= module flag for the fallback client; =doom sync= is unnecessary. This is executable-based selection, not automatic recovery from server failures.

TRAMP retains the existing remote Pyright/BasedPyright client and requires its executable on the remote host. The installed ty and Ruff clients support local buffers only; local availability does not enable either server remotely.

Python buffers enable semantic tokens when the selected server supports them; other languages retain their existing settings. Pyright without semantic-token support continues using ordinary syntax highlighting. With custom themes, =themes-config.el= gives uppercase Python identifiers the shared constant color when syntax highlighting or LSP supplies only a generic variable role. Specific classifications, including modules, functions, types, parameters and enum members, take precedence; comments and strings are excluded. Enum members already use the same constant color. The configuration also repairs Conda environment switching, refreshes Python LSP (including ty, Pyrefly and Ruff) after Conda environment changes, and enables inspection of library source when type information is unavailable. Black is explicitly selected as the default Python formatter; projects can override =apheleia-formatter= through =.dir-locals.el=. Package-specific adjustments remain deferred until their respective libraries load.

* Project symbol overview
[[file:lisp/project-symbols-config.el][project-symbols-config.el]] provides =M-x my/project-symbols=: a query-free Consult overview grouped by symbol kind. It asks active project language servers for each source file's document symbols, including unopened files and unsaved edits in existing buffers. The configuration does not parse definitions itself.

=M-x my/buffer-symbols= uses the same interface for only the current file, including unsaved edits. It requires an active language server with document-symbol support in that buffer, but does not require a Projectile project or enumerate other files. Local variables are included only if the language server returns them under its current settings.

=C-c C-s= toggles between =[Kind]= and =[Source]=, shown in the prompt. Kind groups are alphabetical, with entries ordered by file path and source position within each group. Source shows the buffer in source order, or the project grouped by file then source order; nested symbols are indented when the server returns a hierarchy. Both presentations retain the current query, kind filter, counts in the =<= menu, and selected symbol. Query matches retain the selected ordering rather than using history, candidate length or relevance ranking. =TAB= and =Shift-TAB= cycle kind groups in Kind presentation. In Source presentation they jump to the next or previous top-level symbol (tree root), across files in the project picker, and wrap at either end. Arrow keys still visit every symbol. If a query or kind filter hides a root, root navigation visits its first matching descendant instead.

=my-buffer-symbols-default-order= and =my-project-symbols-default-order= independently accept =kind= (the default) or =source=. With =my-symbols-remember-order= enabled (the default), an explicit toggle overrides that picker's default for the current Emacs session, independently for buffer and project search. Disable it to start from the configured default every time. Queries and kind filters always start fresh; presentation choices are not saved across Emacs restarts.

Both pickers initially select the innermost symbol whose full range contains the cursor in the originating file. Kind presentation puts that symbol at the top, beneath a sticky counted kind heading. The heading remains visible when scrolling within a kind and changes with the topmost result; headings at later kind boundaries remain visible too. Headings are display rows, never selectable candidates. Source presentation centers the enclosing symbol with preceding context above and children/following symbols below, backfilling near the beginning or end to use the available height. Earlier entries remain accessible in either presentation. The query stays empty and the complete list stays searchable. If no enclosing range is available, normal initial selection applies. Up/Down then scroll only enough to keep the selection visible. TAB and Shift-TAB put the selected kind's first result or Source tree root at the top. Changing a query or kind filter preserves the selected symbol if it still matches: Kind places it at the top and Source centers it. If it no longer matches, the first result is selected at the top; clearing a filter preserves the current selection instead of restoring the original symbol. Presentation changes preserve the chosen symbol and apply the destination presentation's placement. The column header and group headings share the existing picker row budget.

Projectile exclusions, environment markers and common dependency/build directories are excluded. Only files supported by an already active language server are queried. Collection runs on each invocation, shows progress and can be cancelled with =C-g=; failures produce a warning. Once collected, =~=-style Orderless filtering applies locally to the whole list. =TAB= and =Shift-TAB= cycle forward and backward between groups. =SPC c j= retains its existing live workspace-symbol search.

Kinds without a dedicated category, such as constructors, appear under Other. The overview contains the definitions exposed by each server; imports, calls and function-local variables are not necessarily returned as document symbols.

Rows have five aligned columns: kind glyph, symbol name, parent symbol, path with line number, and symbol type. Source indentation stays inside the symbol column so glyphs and parents remain aligned. Each text column has a separate width limit and truncates with an ellipsis; widths adapt to narrower windows. Empty parents show =—=. Paths are relative to the Projectile project root (falling back to the language-server root or current file's directory), omit the project directory name, and start with a root-folder glyph (=./= without Nerd Icons). Long paths shorten from the left to retain the filename and line number. Full symbol names, parent names and paths remain searchable. Icons use theme faces; formatting preserves original candidates and distinct jump targets for same-named definitions. A fixed header names the visible columns and reserves one row inside the existing picker height. =my-symbols-column-widths= configures maximum widths independently, and =my-symbols-visible-columns= selects which columns appear, in the standard order; Symbol is always shown.

Symbol previews place the symbol about one quarter of the way down the visible code window, leaving more context below it. Accepting a result preserves its preview screen row when the minibuffer closes, so the newly available space appears below the symbol. =my-symbols-window-position= configures this fraction from the top (default =0.25=; =nil= keeps normal scrolling). The calculation uses the current code window height, excluding the minibuffer. Buffer boundaries can limit how much context fits above the target. Both symbol pickers suppress Nav Flash during previews and accepted jumps so it cannot cover the destination highlight. Cursor placement uses zero-based LSP columns and the provider's negotiated Unicode encoding. Other Consult commands retain their usual scrolling and cursor flashes.

Consult's narrowing prefix is =<= in this configuration. =< a= shows Functions + Methods together, =< F= only Functions, =< M= only Methods, =< s= Structs, and =< c= Classes. =< ?= opens navigation and filter help; =< <= clears the filter. Narrowing preserves the search text and its Orderless syntax, including trailing =~=. The combined filter appears in the which-key prefix popup while the separate Function and Method groups remain available.

Group headings and the =<= menu show counts: =Function (124)= before searching, and =Function (8/124)= for eight query matches. The menu keeps every configured kind visible, including absent kinds with =0= (or =0/0= while searching). Menu counts describe each kind's matches for the query independently of the currently active kind filter, so switching filters remains useful. =Functions + Methods= and =All= have combined counts, and =< ?= shows the same counted kind labels alongside navigation and presentation controls.

Picker-only presentation controls:

- =C-c C-l= toggles Full / Compact columns. Full is the default on every invocation and keeps all configured columns even in narrow windows. Compact hides Parent and Type, keeping the enabled Glyph, Symbol and Path columns with more space for names and paths. It never activates automatically, and toggling does not change the selection, query, filters or searchability of hidden fields. =my-symbols-default-layout= can explicitly select =compact= as the default.
- =C-c C-d= toggles a read-only details panel with the complete selected name, parent, type, project-relative path and source URI. It follows selection changes, including an explicit no-selection message when filtering removes all matches.
- =C-c C-h= or =< ?= toggles help with navigation keys, column/marker explanations, Orderless syntax and counted kind filters.
- =C-c C-w= toggles collection errors. If some files fail, a persistent =[Incomplete: N]= warning remains in the prompt while the successful results stay searchable. Unsupported/excluded files are not reported as failures.
- =C-c C-o= toggles a =•= marker beside the symbol enclosing the original cursor position. =my-symbols-origin-marker= controls the default (enabled), and =my-symbols-origin-marker-face= controls its appearance. A fixed gutter keeps rows and headers aligned; the marker stays attached to that original symbol when you browse, filter, change ordering or switch layouts. It is absent when no enclosing symbol was reported.
- =C-c C-r= toggles a subtle background over the currently previewed symbol's full scope in the source window. =my-symbols-scope-highlight= controls the default (enabled). The scope background matches the theme's current cursor-line highlight. An explicit =my-symbols-scope-face= background overrides this color. The selected-line highlight stays above it. Highlights follow previews and disappear on cancellation, acceptance or exit. Name-only or missing full ranges are not guessed.
- =C-c C-t= toggles subtle Source tree guides for this invocation. =my-symbols-tree-guides= controls the default (enabled). Guides reflect the server's hierarchy; flat responses remain flat.

During symbol preview, the normal cursor-line highlight is temporarily hidden so it does not mark the original line as well as the previewed symbol. It is restored when the picker closes.

Column settings can be changed with =M-x customize-variable= or in configuration. For example (not executed here):

#+begin_example
(setq my-symbols-column-widths
      '((glyph . 2) (symbol . 40) (parent . 20) (path . 60) (type . 14))
      my-symbols-visible-columns '(glyph symbol parent path type)
      my-symbols-default-layout 'full)
#+end_example

Panels appear beside the source without moving focus out of the query. =C-M-v= and =C-M-S-v= scroll the panel; pressing its shortcut again closes it. Panels and their generated buffers are cleaned up when the picker exits. These bindings do not change ordinary source-buffer keys. No extra language-server requests are made for the panels or guides.

* Terminals
[[file:lisp/terminal-config.el][terminal-config.el]] configures Ghostel's Docker shell selection and terminal-specific display settings. Its shell lookup uses the remote user's ID and retains a fallback for containers without a suitable login shell.

The =SPC o t= terminal menu offers =t= for Doom's bottom popup, =T= for a normal terminal buffer, =p= for the plain fullscreen project popup and =m= for its tmux-backed variant. =C-'= opens the plain variant; =C-"= opens the tmux variant. When either fullscreen terminal is visible, either shortcut hides it.

Use =SPC o t P= (=my/terminal-popup-home-toggle=) for a plain fullscreen terminal starting in =~=, or =SPC o t M= (=my/terminal-tmux-home-toggle=) for the home directory's tmux session. Both use the local home directory regardless of the current project or TRAMP connection. The plain home shell persists per Doom workspace; the home tmux session is shared across workspaces and uses the same naming, ownership and cleanup rules as project sessions. Reopening preserves existing shell state. These commands also hide any visible fullscreen terminal before opening another on the next invocation. The project shortcuts =C-'= and =C-"= retain their existing meanings.

=C-'= opens or focuses a separate persistent project terminal. In graphical Emacs it uses a child frame filling the parent Emacs frame; terminal Emacs uses a large bottom popup. Pressing the shortcut inside it hides the terminal without stopping its shell. New shells start at Doom's detected project root, falling back to the current directory outside projects. Each full project-root path and Doom workspace gets its own shell. The terminal retains its state when hidden and does not affect the windows or Olivetti centring behind it. For minibuffer commands such as =M-x=, use =C-'= to return to the editor first. The bottom popup and normal terminal use Emacs's standard minibuffer. Its borderless fullscreen frame uses an 8-pixel inset on all four sides and excludes spacious-padding spacing; other frames retain their padding. Alternate-screen backgrounds extend over the unused pixels at the right and bottom edges, without changing the font size or clipping terminal cells. =SPC o t t= and =SPC o t T= retain Doom's original window layouts and use independent shells.

The tmux variant creates a session at the current local project root when needed, or attaches its existing session. Names start with =emacs-=; a project named =api= normally gets =emacs-api=. If that name collides, the nearest differing parent directories disambiguate it, for example =emacs-personal-api= or =emacs-other-apps-api=. The full canonical root is recorded in =@emacs-project-root=; =@emacs-terminal-owner= identifies this feature and =@emacs-terminal-uuid= gives each session its own version-4 UUID. Later visits find the same session by its metadata, even if renamed. Older =emacs-= sessions carrying the exact project-root tag are upgraded when reopened; unrelated sessions are not adopted by name alone. Projects in different Doom workspaces share that project session, while their Ghostel client buffers remain separate. The plain shell and tmux client also have separate buffers in the same fullscreen frame. Hiding preserves a client; detaching closes the client but leaves the tmux session running, and the next =C-"= attaches a new client. Closing the session detaches its client rather than moving it into another session. Normal tmux sessions and Doom's other terminal layouts are unchanged. Remote TRAMP projects can continue using the plain terminal; automatic project tmux sessions currently support local roots.

Use =M-x my/terminal-tmux-list= to inspect managed local sessions, project roots and UUIDs in a bottom popup; =RET= opens the selected session in the fullscreen terminal, =g= refreshes the table and =q= closes it. =M-x my/terminal-tmux-kill-project= removes managed sessions for the current project, and =M-x my/terminal-tmux-kill-all= removes all managed local sessions. Both removal commands list the affected names and require confirmation because they terminate shells and running programs. Ownership and UUIDs are rechecked before deletion; manually created or untagged sessions are excluded.

All Ghostel terminals, including =SPC o t t=, =SPC o t T= and =C-'=, temporarily disable Evil and use direct char-mode input while an alternate-screen application runs. This covers applications such as tmux, Neovim and Yazi, rather than every foreground command. Returning to the shell restores the previous Evil and input settings; a deferred redraw recovers synchronized output left active after detaching. =Ctrl += / =Ctrl -= scale the terminal buffer even inside these applications; =Cmd += / =Cmd -= retain Doom's global font zoom.

The floating terminal is omitted from the =SPC b b= workspace buffer picker; it remains available through =C-'= and the broader =SPC b B= buffer picker. Other Ghostel terminals remain in the workspace picker. At the shell, the floating terminal enters Evil insert state when opened. Both =C-'= and =C-"= continue to hide it in either input mode. Its fullscreen layout, insets and edge-background fill apply only to this floating terminal. For command documentation, use =C-h k C-'= or =C-h f my/terminal-popup-toggle= from an editor buffer.

* Signature help
[[file:lisp/signature-config.el][signature-config.el]] configures automatic LSP signature help. By default, it uses a full-width
bottom window with arguments and documentation. Its fixed pixel height follows the M-x/Vertico row count and font
size, capped at 45% of a small frame. Long lines wrap instead of being truncated;
the height does not change with the number of arguments. Wrapped parameter rows
with a simple ~name: value~ or ~name = value~ prefix continue beneath the value,
using visual hanging indentation without inserting spaces into the server text.
Unrecognized prefixes and layouts too narrow for useful indentation retain normal
wrapping. Return types following an explicit arrow or colon after a reliably
identified argument list appear on a separate line after one blank line, with
bold, theme-specific type coloring. The server's return marker and type text
remain unchanged. LSP does not provide a separate return-type range, so styling
requires a server-supplied parameter boundary. Empty or missing parameter metadata
(including omitted implicit receivers) and unsupported return syntax retain the
server's layout. Signature help highlights
the active parameter in bold with the theme's keyword color and a subtle background,
while slightly dimming other signature text. These fallback colors are derived
from the active theme's existing faces; explicit theme and user face customizations
retain priority. This uses lsp-mode's native
server-supplied parameter ranges. Signature text and its existing properties are
preserved. Line breaks are inserted before parameters only when the server supplies
validated ranges or unambiguous labels; otherwise the original layout remains.
No types, defaults or separators are parsed, and no union expansion or inferred
syntax coloring is applied.
The signature window scrolls to center the active parameter where possible without
taking typing focus. Entering Evil Insert state inside an existing call, or moving
into one while inserting, activates signature help after a short idle pause.
The server decides whether a call is present; leaving Insert state cancels help.
A horizontal divider separates the signature from server-provided documentation.
When available, documentation for the active parameter appears under an
=Active parameter= heading alongside the signature documentation. Plain text
and Markdown use lsp-mode's renderer, with a plain-text fallback if rendering
fails. No hover request, inferred type information or extra server request is
used to fill missing documentation. =lsp-signature-doc-lines= still controls the
documentation limit. Valid overload selection and signature-level active
parameter metadata take precedence; missing or invalid indexes use protocol
defaults. Parameter offsets are validated and converted from UTF-16 units,
and cached server labels are never modified by highlighting.
Use =M-x my/signature-presentation= to choose =bottom=, =floating= (a bordered
box near the cursor), or =compact= (an echo-area line). Switching immediately
closes the old view and redraws any active signature without a server request.
Only =bottom= includes server-provided documentation. In terminal Emacs,
=floating= falls back to a bottom window. The command changes this session;
Customize =my-documentation-signature-style= to save a persistent preference.
=K= opens the separate documentation reading view as usual.

* Documentation reading view
[[file:lisp/documentation-config.el][documentation-config.el]] preserves Doom's normal =K= lookup in source.
Press =K= again within one second to expand its result into a single
Olivetti-centered window. Press =q= to restore the previous layout.

LSP documentation is a reading view. Arbitrary identifiers in prose or examples
are not resolved: =gd= does nothing, and =K= only expands a prompt repeat of
the initial lookup. Ordinary source =K= and =gd= remain available as usual.
This avoids guessing imports, constructing synthetic LSP documents or choosing
unrelated symbols from documentation text. The language targets and verification
policy are recorded in [[file:AGENTS.md][AGENTS.md]].

Code examples keep syntax highlighting for their declared language, falling
back to the source language for unlabeled blocks. Python prefers Tree-sitter
when its grammar is available and falls back to ordinary Python highlighting.
Prompts and output remain intact. Editing-mode hooks are suppressed; examples
never activate environments or language servers. Rendering normalizes ignored
trailing whitespace on matching Markdown closing fences. Rendered code
backgrounds match the Help surface without changing ordinary Markdown buffers.

Explicit documentation links remain buttons: =TAB=/=Shift-TAB= traverses them
and =RET= follows their supplied targets through the normal LSP link handler.
=C-o= or =<= goes back through native Help history; =C-i= or =>= goes forward.
History reuses cached documentation without another LSP request. Refreshing a
page does not add a duplicate history step or discard Forward. Graphical Emacs
keeps =TAB= for links; terminals that send the same event for =TAB= and =C-i=
use it for Forward, with =Shift-TAB= available for links.

Use =C-c C-o= or =M-x my/documentation-open-source= to leave LSP Help and
open the documented topic's actual source. This asks the original server at
the saved source position, regardless of the cursor position in Help. Multiple
definitions require selection; missing/unreadable source produces an explicit
error. Source opens with its existing permissions and read-only settings.
Normal source navigation does not automatically enable View mode; existing
explicit View mode is preserved.

In fullscreen, the bottom mode line identifies the topic and server, with an
accented book icon and bold =Documentation= label. Terminal Emacs uses =[D]=.
There is no top header. Buffer zoom (=C-== / =C--=) also works in Evil motion
state. Fullscreen uses the normal theme background to match its fringes;
Solaire's popup background is restored on leaving fullscreen.

=M-x my/documentation-reopen= reopens the last page at the bottom;
=M-x my/documentation-reopen-centered= reopens it centered. Both retain contents,
cursor position and history. External browsers and asynchronous results not
displayed during the initial lookup are not expanded. Use =C-h f= for command
documentation. Focused tests live in
[[file:lisp/tests/documentation-tests.el][documentation-tests.el]].

* Git
Code Review reuses the Forge credential entry (=USERNAME^forge=). Its legacy GraphQL dependency is loaded when needed for compatibility with the installed Ghub version; this does not create or submit reviews automatically. The review buffer consistently opens in a right-hand popup occupying 60% of the frame width, including when reopening or refreshing a review.

Use =SPC g n= (=my/magit-status-fullscreen=) to open Magit status across the current frame with normal Olivetti centering. =SPC g e= (=my/magit-status-fullwidth=) uses the full width without centering. In either view, =q= restores the previous window layout and clears the temporary display override. =SPC g g= and =SPC g G= retain Doom's normal display behavior.

Logs, revisions, diffs and other Magit views opened from the full-width view inherit its centering exclusion. Opening a reused view from a normal Magit entry point clears that exclusion, so it does not affect later centered sessions.

[[file:lisp/magit-config.el][magit-config.el]] enables visible-line relative numbers in Magit buffers for counted Evil motions such as =5j= and =3k=. Folded section contents do not contribute hidden lines to the count; =TAB= toggles the current section. Counted upward motions repeat single visible-line steps to avoid an Emacs 29 off-by-one movement at folded section boundaries. Use =D /= in Magit to filter changes by directory. Selecting the repository root removes the filter. Use =D C= to clear active and remembered file filters. Commit-age annotations respect Magit's margin visibility setting, so Olivetti's outer padding cannot expose disabled annotations.

[[file:lisp/git-config.el][git-config.el]] provides shared Git commands outside Magit.
The =SPC g v= group is labelled =visual selection=.
In a saved source buffer, select lines with Evil =V= (or an ordinary active
region), then use =SPC g v s= (=my/git-stage-selection=) to stage only changed
lines in that range, splitting hunks. =SPC g v h=
(=my/git-stage-selected-hunks=) stages every complete Git hunk the selection
touches, including its three context lines. =SPC g v d=
(=my/git-discard-selected-hunks=) discards complete unstaged hunks touched by
the selection after showing a read-only diff preview. The preview displays the
existing changes that will be undone, including changes outside the selection
within the same hunk. Scroll normally, press =c= (or =C-c C-c=) to confirm, or
=q= (or =C-c C-k=) to cancel. Confirmation rejects changes to the source buffer,
file or index made since the preview was prepared. It restores those hunks from the index and
refreshes the source buffer; staged changes and untouched hunks remain intact.
Discarding can remove changes outside the selection within the same hunk.
These commands do not open Magit.
Both staging commands preserve prior staged changes and working-tree contents. A character
selection stages whole touched lines; visual block selections are rejected.
Deletion-only changes are anchored to the preceding visible line, or line one
at the start of the file. Exact selection staging rejects a selection that cuts
through a replacement block with unequal old/new line counts: select the whole
block or use the hunk command rather than guessing which removed lines belong
to which replacements. Staging new files needs intent-to-add (=git add -N FILE=)
first; discarding hunks in intent-to-add files is unsupported.
Binary files, merge-conflicted files and remote buffers are unsupported; unsaved
buffers or externally changed files must be reconciled before staging.

* Buffer centring
Olivetti uses 45% of the available window width, so font zoom changes the text
size without moving the centering borders. The width still follows window
resizing, with normal character-cell rounding of the margins.
Use =M-x my/olivetti-reset-width= to reset the current buffer's width after
=olivetti-expand=, =olivetti-shrink= or =olivetti-set-width=. The command reads
the configured default (currently 45%) and preserves centering and font zoom.
Workspace creation and restoration suspend automatic centering and border updates until the complete window layout is available, preserving saved splits when switching or deleting workspaces.

[[file:lisp/olivetti-config.el][olivetti-config.el]] centres visible file, Dired and shell buffers and manages their borders. Centring is disabled whenever editing windows are side by side, including terminal and other sidebar windows, and returns when those splits are closed. A left Treemacs sidebar instead uses the existing left padding: the text stays in its original position when enough padding is available, and its margins are restored when Treemacs closes. If the sidebar exceeds that padding, the text moves only as needed to fit. Treemacs toggling with ordinary editing splits is unchanged. Doom popup buffers, PDF viewers and the clock popup are excluded. Full terminal buffers (=SPC o t T=) can be centred; terminal popups (=SPC o t t=) keep their normal width. Use =SPC t o= to toggle this behaviour.

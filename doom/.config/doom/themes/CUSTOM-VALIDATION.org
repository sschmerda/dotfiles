* Bold modules and regional colors — 2026-11-05
All 29 custom themes explicitly emphasize recognized namespaces with bold weight,
including module names in imports and namespace references. The global Doom bold
opt-out is preserved. Landscape module colors now follow their regional palette
rather than assigning teal universally. The namespace checks cover bold enabled
and disabled, contrast on all three surfaces, and separation from types,
functions and ordinary text.

* Separate module colors — 2026-11-05
All 28 combined ERT tests pass. All 29 palettes assign namespaces a separate
palette-specific color, with at least 4.5:1 contrast on the normal, alternate and current-line
backgrounds. Module colors remain perceptually distinct from types, functions
and ordinary text. LSP namespaces and optional external Tree-sitter namespace
faces share this role. Existing type and function colors are unchanged.

The shared mapping audit preserves intentional groupings: functions/methods,
numbers/constants and uniform brackets/delimiters. Python syntax-only module
and decorator classification remains dependent on the parser; semantic tokens
supply the extra categories when available.

* Declaration-only parameter highlighting — 2026-11-05
All 27 combined ERT tests pass. A real lsp-mode token-fontification test checks
parameter declarations, ordinary body references, keyword labels versus values,
unchanged type/function faces, retained deprecation styling and isolation from
non-custom themes. Python Tree-sitter supplies call-label context; the server's
declaration modifier supplies declaration context without grammar changes.

The running Python =x_t= example was refontified and inspected: header =x=/=y=
retain the secondary parameter face with a neutral declaration marker, and
their references after =return= use the ordinary variable face. Parameter,
variable and type colors remain distinct. Buffer text, modified state, active
theme and configured default were preserved; no server restart was needed.

* Argument and punctuation hierarchy — 2026-11-04

* Integration and limits
The tested shared engine covers standard/built-in Tree-sitter faces, LSP
semantic faces, Corfu/Vertico/Orderless, diagnostics, Org/Markdown, Magit/diff-hl,
Solaire, modeline and ANSI/Ghostel inheritance. The custom layer adds only
palette-specific overrides. It does not change parser rules, fonts, Org view
modes, server configuration, environment activation or keybindings.

The source VS Code theme uses TextMate per-language scopes, which Emacs cannot
reproduce exactly through generic faces. The fixture captures use ordinary
Python fontification; actual semantic-token classifications depend on the
attached server. No new language-server sessions, remote connections, package
upgrades or personal note/database access were required for this work.

Full interactive completion/merge workflows, native terminal application
rendering, cross-platform GUI/font rendering and 256/16-color terminal
approximations were not re-tested for these palettes. Existing user face
remaps, Spacious Padding and Olivetti can override decorative surfaces.
